# Provisioning the Home Assistant integration identity

The integration will receive a short-lived, single-use bootstrap capability through Home Assistant's supported Supervisor discovery flow, then exchange it with the add-on over the internal `hassio` network for a distinct system credential. Discovery is a user-confirmed config-entry flow, not silent setup. Only the system credential authenticates the integration afterward; it is never sent through discovery, and the optional LAN host port is not required. Re-setup rotates via the existing credential, while removal attempts revocation; cleanup is best-effort when the add-on is unavailable. Store the credential in config-entry data, treating HA backups and host administrators as part of the trust boundary because the documented storage contract does not promise encryption at rest. Do not grant the add-on Home Assistant administrative API access. The bootstrap secret's confidentiality and the complete discovery/config-entry lifecycle remain gated on live Home Assistant/Supervisor validation.
