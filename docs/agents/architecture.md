# Architecture

## Public surfaces

| Surface | Location | Responsibility |
| --- | --- | --- |
| Home Assistant app | `repository.yaml`, `ha-finassists/` | App repository identity, add-on metadata, runtime image, Ingress entry point, and persistent data mapping. |
| Bun application | `ha-finassists/src/server.ts`, `ha-finassists/src/app-bootstrap.ts`, `ha-finassists/src/app-container.ts`, `ha-finassists/src/config.ts` | Runtime entry point, startup glue, the InferDI container that composes repositories and use cases, and validated environment/add-on configuration. |
| HTTP API | `ha-finassists/src/modules/api/infrastructure/http/` | Inbound HTTP adapter (declarative Hono routes with Zod request validation; use cases are resolved from the InferDI scope exposed as `c.var.di`), security headers, and web asset delivery; application behavior is delegated to the owning modules. |
| Home Assistant identity | `ha-finassists/src/modules/home-assistant/` | Domain actor types plus the Ingress infrastructure adapter that resolves actors only from a trusted Supervisor peer. |
| Web interface | `ha-finassists/src/app/` | Modular React 19 UI with JSON translations and CSS Modules, rendered by a Bun SSR bundle and hydrated from a separately built client bundle. |
| Native integration | `custom_components/ha_finassists/` | Home Assistant config flow, REST client, recorded monthly sensors, scheduled forecast and due sensors, transaction and scheduled-movement services, and the bundled Lovelace card served as a static module. The integration uses a distinct system credential, not a person's token. |

## Runtime boundaries

`ha-finassists/src/server.ts` is the runtime entry point and delegates startup to `ha-finassists/src/app-bootstrap.ts`, which builds the InferDI container in `ha-finassists/src/app-container.ts` and passes it to `createServer`. Tests build a minimal container with `createHttpContainer`. The HTTP API adapters live under `ha-finassists/src/modules/api/infrastructure/http/`; they expose the authenticated `/transactions` routes and the stateless MCP transport while delegating domain behavior to the owning modules. The only financial module is `ha-finassists/src/modules/ledger/` (the `Transaction`, `Category` and `ScheduledTransaction` aggregates with their use cases, backed by SQLite), while the technical `ha-finassists/src/modules/scheduling/` module provides the `Scheduler` port and its Bun cron adapter for the scheduled-posting job that runs at startup and periodically. Personal token behavior remains in `ha-finassists/src/modules/tokens/`, and the Home Assistant system identity has its own credential lifecycle. Home Assistant actor types live in the domain layer, while Supervisor header and peer validation live under `ha-finassists/src/modules/home-assistant/infrastructure/ingress/`. The React UI lives under `ha-finassists/src/app/`, with the client hydration entrypoint at the app root, document composition in `shell/`, reusable UI in `components/`, feature flows in `features/`, locale data in `i18n/`, and shared CSS in `styles/`. `LocaleProvider` receives the request language through the app tree in both SSR and hydration; do not store request-specific locale state in a server-global singleton. Use `@modules/*` and `@app/*` TypeScript aliases across modules; keep relative imports within a layer. Production Ingress identity always comes from the trusted Supervisor peer; only development configuration may supply a mock actor. The native integration's automated requests use a separate system credential and stable integration actor, never a personal token. Verify the credential lifecycle and network boundary in a supported live Home Assistant/Supervisor instance before releasing the native integration.

## Build output

The repository root is a Bun workspace whose only package is `ha-finassists`, so the app owns its source, manifests and scripts while the root keeps the integration, the release tooling and the shared configuration. `bun run build` at the root delegates to the app package, which coordinates `build:server` and `build:web` and writes production artifacts to the ignored `ha-finassists/dist/` directory. `build:web` separately builds the browser client and Bun SSR renderer, and publishes the SSR renderer's emitted CSS (global and CSS Module styles) as `dist/styles.css`. `bun run dev` runs the TypeScript server under Bun watch and compiles the client, CSS, and SSR renderer in memory; a development-only version endpoint lets browser clients reload after source changes. The HTML shell is streamed from the SSR renderer and hydrates from a same-origin bundle. The shared UI is split into reusable components and feature modules, translations live in JSON locale files, and component styles use CSS Modules without a runtime CSS dependency.
